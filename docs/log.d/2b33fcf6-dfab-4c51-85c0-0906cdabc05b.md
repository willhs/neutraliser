## [2026-11-15] fix | 7.1 no longer fails every sweep after a full measure (research 0003 finding 13)

Reproduced on a synthetic FLAC 7.1 `.mp4` (`normalised track has 5 channels, source has 8`, after the measure). Cause: ffmpeg's AC-3 / E-AC-3 stop at 5.1, but `CodecChoice` still picked them for 7.1 (and kept E-AC-3 7.1 as E-AC-3 in MKV). Now `CodecChoice` sends anything over 5.1 channels to FLAC where the container takes it (a codec change, so still behind `--allow-codec-change`), and has no encoder where it doesn't. New guard `Guards#channel_count` skips that file before the measure, with reason `too_many_channels` and a left record, whatever flags are given. Stereo and 5.1 decisions unchanged. Lossy 7.1 (AAC, Opus) was not added: a product call, so the safe skip is the default. README, data_contracts, AGENTS and finding 13 updated; real-ffmpeg spec in `spec/sceptical_review_spec.rb`.
